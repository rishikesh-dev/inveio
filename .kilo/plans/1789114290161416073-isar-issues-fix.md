# Fix Isar Integration Issues

## Problem

Isar is partially integrated using `isar_plus` (v1.3.x), but the project is missing critical code generation dependencies, has misaligned initialization order, and contains stale documentation referencing the old `isar` package. This results in compile-time failures for generated schema symbols and potential runtime crashes on first launch.

## Issues Found

### 1. Missing Code Generation Dependency
**File**: `pubspec.yaml` lines 28-41
**Impact**: Compile-time — generated schema symbols (`UserModelSchema`, `TransactionModelSchema`) and Isar collection extension methods (`put`, `where`, `filter`, `getByUid`, `watch`, etc.) are undefined.
- `isar_generator` is absent from `dev_dependencies` even though README line 56 and `assets/plan/PROJECT_STRUCTURE.md` line 169 document it.
- Both models reference generated `.g.dart` files that do not exist:
  - `lib/profile/data/models/user_model.dart` -> `user_model.g.dart` (missing)
  - `lib/transaction/data/models/transaction_model.dart` -> `transaction_model.g.dart` (missing)

### 2. Dependency Version Mismatch
**File**: `pubspec.yaml` lines 28-29
**Impact**: Potential version conflicts at runtime.
- `isar_plus: ^1.3.9` vs `isar_plus_flutter_libs: ^1.3.8` (minor version mismatch).
- `pubspec.lock` shows both resolved at 1.3.9, but `pubspec.yaml` allows the libs package to resolve differently.

### 3. Incorrect Isar Initialization API
**File**: `lib/shared/dependencies/app_dependencies.dart` line 58
**Impact**: Runtime crash on first launch.
- `await Isar.initializeIsarCore(download: true);` uses standard Isar API.
- `isar_plus` 1.x may require a different initialization pattern (e.g., `IsarFlutter.initializeIsarCore()`).

### 4. Schema Registration Fails (Without Generated Code)
**File**: `lib/shared/dependencies/app_dependencies.dart` line 72
**Impact**: Compile-time error — `schemas: [UserModelSchema, TransactionModelSchema]` references symbols that don't exist without generated code.

### 5. Initialization Order Violation
**File**: `lib/main.dart` lines 20-26
**Impact**: Potential crash if singletons are eagerly resolved.
- `initDatabase()` opens Isar with schemas, but runs AFTER `initUser()`, `initAuth()`, and `initOnboarding()`.
- README lines 332-339 documents a different order where `initDatabase()` runs before `initUser()`/`initAuth()`.

### 6. Non-Standard Android Build Directory
**File**: `android/build.gradle.kts` lines 8-17
**Impact**: Potential native library linking issues.
- Build directory overridden to `../../build` instead of standard location, which may interfere with Flutter plugin resolution (including native Isar libraries).

## Solution Approach

### Step 1: Add Missing Code Generation Dependency
- Add `isar_generator: ^1.3.9` to `dev_dependencies` in `pubspec.yaml` (matching `isar_plus` version).
- Remove or update stale references to `isar: ^3.1.0+1` in `assets/plan/PROJECT_STRUCTURE.md` lines 143-145 and 169.

### Step 2: Run Code Generation
- Execute `dart run build_runner build --delete-conflicting-outputs` to generate `.g.dart` files for both models.
- Verify `lib/profile/data/models/user_model.g.dart` and `lib/transaction/data/models/transaction_model.g.dart` exist.

### Step 3: Align Dependency Versions
- Update `isar_plus_flutter_libs` constraint from `^1.3.8` to `^1.3.9` to match `isar_plus`.
- Run `flutter pub get` to resolve and lock consistent versions.

### Step 4: Verify Initialization API
- Check `isar_plus` 1.3.9 API docs/source to confirm correct initialization method.
- Update `lib/shared/dependencies/app_dependencies.dart` line 58 if needed (e.g., `IsarFlutter.initializeIsarCore()`).

### Step 5: Fix Initialization Order
- Reorder `main.dart` so `initDatabase()` runs BEFORE `initUser()` and `initAuth()`, matching README documentation (lines 332-339).

### Step 6: Fix Android Build Directory
- Remove or simplify the non-standard build directory override in `android/build.gradle.kts` lines 8-17 to use default Flutter build path.
